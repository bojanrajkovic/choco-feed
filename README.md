# choco-feed

A static [Chocolatey](https://chocolatey.org/) package feed for
[runny](https://github.com/bojanrajkovic/runny), served from GitHub Pages.

It is a NuGet **v3** feed generated by [Sleet](https://github.com/emgarten/Sleet) —
plain files, no server. This repository is the Chocolatey counterpart to
[homebrew-tap](https://github.com/bojanrajkovic/homebrew-tap).

## Use it

```powershell
choco source add -n=runny -s=https://bojanrajkovic.github.io/choco-feed/index.json
choco install runny
```

Upgrades then work the usual way:

```powershell
choco upgrade runny
```

Pre-release builds are published here too, and Chocolatey needs to be asked for them:

```powershell
choco install runny --pre
```

**Chocolatey 2.4.1 or newer is required.** Chocolatey has consumed NuGet v3 feeds
since 2.0.0, but on v3-only feeds — which is what Sleet produces — installing an
explicit `--version` did not resolve until the fix in 2.4.1
([choco#3396](https://github.com/chocolatey/choco/issues/3396)).

The package delivers the `runnyd.exe` and `runnyctl.exe` binaries and registers no
service; see runny's [deployment guide](https://github.com/bojanrajkovic/runny/blob/main/docs/deploy.md)
for `runnyctl install-daemon`.

## Contents

Everything except this README is generated. Do not hand-edit it — the next release
overwrites it.

| Path | What |
| --- | --- |
| `index.json` | the v3 service index; entry point for the `-s` URL above |
| `flatcontainer/` | the packages themselves (`.nupkg`) and their extracted `.nuspec` |
| `registration/` | version metadata Chocolatey reads to resolve and compare versions |
| `search/`, `autocomplete/` | static query results |
| `sleet.json` | Sleet's feed config — the `baseURI` here is baked into every generated file |
| `sleet.settings.json`, `sleet.packageindex.json` | Sleet's own bookkeeping |
| `.nojekyll` | keeps GitHub Pages from running the files through Jekyll |

Releases push to this feed from runny's release workflow.
